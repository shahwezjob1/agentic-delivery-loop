# Dev Agent Worker Repository Map

## 1. Purpose

This file is the implementation inventory for the Dev Agent Worker. It defines the planned source files, ownership boundaries, major types and exported signatures. Coding agents must keep responsibilities in the listed modules and must not introduce Pi, repository cloning, shell execution, public backend routes or unrelated abstractions.

## 6. Domain modules

Dev defines no local Domain types or Domain service interface. `TicketDto`, `RpcResult<T>` and the Domain inputs are imported from `@agentic-delivery-loop/contracts`; the `DOMAIN_API` binding type comes from the Wrangler-generated `worker-configuration.d.ts`.

### `src/domain/domain-client.ts`

Exports:

```ts
import type { RpcResult, TicketDto } from '@agentic-delivery-loop/contracts';

export class DomainRpcError extends Error {
  constructor(
    readonly code: string,
    message: string,
  ) {
    super(message);
    this.name = 'DomainRpcError';
  }
}

export function unwrapRpcResult<T>(result: RpcResult<T>): T {
  if (!result.ok) throw new DomainRpcError(result.error.code, result.error.message);
  return result.data;
}

export class DomainClient {
  constructor(service: Env['DOMAIN_API'], logger: DevLogger);

  getTicket(input: { ticketId: string }): Promise<TicketDto>;
  startOldestAcceptedTicket(): Promise<TicketDto | null>;
  saveTicketPullRequestUrl(input: { ticketId: string; pullRequestUrl: string }): Promise<TicketDto>;
  completeTicket(input: { ticketId: string }): Promise<TicketDto>;
}
```

Domain methods used (authoritative signatures come from the generated binding type):

```text
getTicket({ ticketId })                                 -> Promise<RpcResult<TicketDto>>
startOldestAcceptedTicket()                             -> Promise<RpcResult<TicketDto | null>>
saveTicketPullRequestUrl({ ticketId, pullRequestUrl })  -> Promise<RpcResult<TicketDto>>
completeTicket({ ticketId })                            -> Promise<RpcResult<TicketDto>>
```

Responsibilities:

- Be the only wrapper used by Dev tools and lifecycle service for Domain RPC.
- Call `this.service.x({ ... })` with object inputs, then `unwrapRpcResult()`, and return the direct business value.
- Add structured start/success/failure logging.
- Surface failures as `DomainRpcError` with `code: string`, never custom `instanceof` across the RPC boundary.
- Send only the PR URL to Domain; PR number and branch stay in `DevAgentState`.
- Do not retry or call public HTTP routes.

- Define only the Dev-local verification tool input.

### `src/verification/verification.service.ts`

Exports:

```ts
export class VerificationService {
  constructor(wingmanNamespace: Env['WINGMAN_AGENT'], logger: DevLogger);

  verifyDeployedWingman(input: VerifyWingmanCapabilityInput): Promise<WingmanVerificationResult>;
}
```

Internal flow:

```ts
const conversationId = crypto.randomUUID();
const wingman = await getAgentByName(env.WINGMAN_AGENT, conversationId);
const result = await wingman.invokeTurn({ prompt: input.prompt });
const verified = result.toolCalls.some((call) => call.toolName === input.expectedToolName);
const toolsCalled = result.toolCalls.map(({ toolName }) => ({ toolName }));
```

Responsibilities:

- Create one fresh Wingman conversation per attempt.
- Await complete RPC result without a custom application timeout.
- Perform exact, case-sensitive tool-name matching.
- Return normal Wingman `UIMessage` and simple tool-call log.
- Never assess arguments, output correctness or assistant-text correctness.
- Never save the fresh Wingman conversation ID into long-lived Dev state.
- Never send expected tool name to Wingman.

There is no `verification-prompt.ts`; the model supplies both prompt and expected tool name.

## 11. Cross-worker contracts required from other services

These files are not implemented inside the Dev Worker, but code generation must compile against them.

### Domain API Worker

Must expose the typed Service Binding RPC methods `getTicket({ ticketId })`, `startOldestAcceptedTicket()` (transactional), `saveTicketPullRequestUrl({ ticketId, pullRequestUrl })` and `completeTicket({ ticketId })`, each returning `Promise<RpcResult<...>>`.

### Wingman Agent Worker

Must export `WingmanAgent` as a cross-worker Durable Object class (worker `agentic-delivery-loop-wingman-agent`) and expose:

```ts
invokeTurn(input: InvokeWingmanTurnInput): Promise<WingmanTurnResult>;
```

`invokeTurn()` runs Wingman's normal turn executor (detail owned by the Wingman LLD) and returns `{ responseMessage, toolCalls }`. It must not accept the expected tool name or return a verification judgment.

### UI Worker

Must forward Dev Agent WebSocket/HTTP agent traffic through its private Dev Worker Service Binding. Browser code stores Dev conversation ID in `localStorage` and reconnects after refresh.

## 13. Forbidden repository additions

The coding agent must not add:

- Pi/Think/OpenCode dependencies.
- `pruneMessages()` or custom conversation pruning.
- Git clone/worktree libraries.
- Shell, sandbox or code execution tools.
- GitHub Actions control.
- Merge/deploy/rollback tools.
- Public Domain, Wingman or Dev APIs.
- Queue, Workflow, claim/lease/lock or concurrency tables.
- Generic retry/reconciliation framework.
- `DRY_RUN` mode.
- Test packages or test directories.
- A second model provider.
- A separate verification prompt generator.
