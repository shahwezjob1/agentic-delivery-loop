# UI Worker Repository Map

## 1. Purpose

This repository map is the file-level implementation contract for the UI Worker. It must be read with `ARCHITECTURE.md`. The coding agent may make small mechanical adjustments required by the package versions pinned in the root dependency baseline, but it must preserve the ownership boundaries, public routes, DTOs, and behavior described here.

## 3. Root configuration files

### `package.json`

Owns UI Worker scripts and exact dependencies.

Scripts:

```jsonc
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "typecheck": "tsc --noEmit",

    "cf:types": "wrangler types -c wrangler.jsonc -c ../domain-api-worker/wrangler.jsonc -c ../wingman-agent-worker/wrangler.jsonc -c ../dev-agent-worker/wrangler.jsonc",
    "deploy": "wrangler deploy",
  },
}
```

`cf:types` supplies the UI, Domain API, Wingman, and Dev Agent configurations so the generated `Env` includes the typed `DOMAIN_API` Service Binding.

Requirements:

- Uses the exact versions from the root dependency baseline (`docs/ARCHITECTURE.md` → Dependency baseline, root `pnpm.overrides`, committed `pnpm-lock.yaml`). Module implementations must not independently select or change versions. No `^`, `~`, `latest`, or `*`.
- Include `@agentic-delivery-loop/contracts` (`workspace:*`), React, Vite, TypeScript, Hono, Wrangler, Cloudflare Vite integration if used, `agents`, `@cloudflare/ai-chat`, and only the AI SDK packages required by the selected APIs and shared `UIMessage` type.
- Do not add React Router, Redux, Zustand, TanStack Query, a CSS framework, or a component library.
- Do not add test packages.

### `wrangler.jsonc`

Declares:

- UI Worker name `agentic-delivery-loop-ui` and entrypoint.
- Current implementation compatibility date.
- Static assets or compatible Cloudflare Vite setup.
- SPA fallback.
- Worker-first paths for `/api/*` and `/agents/*`.
- `DOMAIN_API` Service Binding (typed RPC).
- `WINGMAN_AGENT` ordinary Service Binding (`Fetcher`, fetch/WebSocket forwarding only).
- `DEV_AGENT` ordinary Service Binding (`Fetcher`, fetch/WebSocket forwarding only).
- Observability settings if already part of repository convention.

Required behavior:

```jsonc
"name": "agentic-delivery-loop-ui",
"services": [
  { "binding": "DOMAIN_API", "service": "agentic-delivery-loop-domain-api" },
  { "binding": "WINGMAN_AGENT", "service": "agentic-delivery-loop-wingman-agent" },
  { "binding": "DEV_AGENT", "service": "agentic-delivery-loop-dev-agent" }
],
"assets": {
  "binding": "ASSETS",
  "not_found_handling": "single-page-application",
  "run_worker_first": ["/api/*", "/agents/*"]
}
```

Do not add D1, Vectorize, Workers AI, Workflow, Durable Object namespace, GitHub, or secret bindings to the UI Worker.

### `vite.config.ts`

Configures React and the baseline-pinned Cloudflare Vite integration where applicable. It must build the browser application and Worker entrypoint in the supported manner for the selected plugin version.

Do not create a custom development proxy that changes production route semantics.

### `UI_SMOKE_TEST.md`

Short manual smoke-validation checklist (local run and after `wrangler deploy`) described in `ARCHITECTURE.md`. It must remain manual and must not introduce a test runner.

## 4. Worker files

### `src/worker/env.ts`

Re-exports the Wrangler-generated `Env` from `worker-configuration.d.ts`. It does not hand-write binding types and does not declare a Domain API service interface.

Expected generated bindings:

| Binding         | Type                                                                                                                       |
| --------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `ASSETS`        | `Fetcher`                                                                                                                  |
| `DOMAIN_API`    | Generated Service Binding type for the Domain API `WorkerEntrypoint` (from `cf:types` with the Domain API config supplied) |
| `WINGMAN_AGENT` | `Fetcher` (ordinary Service Binding)                                                                                       |
| `DEV_AGENT`     | `Fetcher` (ordinary Service Binding)                                                                                       |

Cross-app source imports (for example from `../../domain-api-worker/src`) are forbidden.

### `src/worker/index.ts`

Top-level Worker entrypoint.

Major export:

```ts
export default {
  fetch(request: Request, env: Env, ctx: ExecutionContext): Promise<Response>;
};
```

Routing algorithm:

1. Read `new URL(request.url).pathname`.
2. If it starts with `/api/`, delegate to `app.fetch(request, env, ctx)`.
3. If it starts with `/agents/wingman-agent/`, call `proxyAgentRequest(request, env.WINGMAN_AGENT)`.
4. If it starts with `/agents/dev-agent/`, call `proxyAgentRequest(request, env.DEV_AGENT)`.
5. If it starts with `/agents/` but matches neither supported Agent, return `404`.
6. Delegate all remaining requests to `env.ASSETS.fetch(request)` if the selected Static Assets and Vite setup requires an explicit fallback. If routing is handled before the Worker by Wrangler configuration, preserve the equivalent behavior supported by that version.

The implementation must return upstream Agent responses directly and must not wrap them in Hono.

### `src/worker/app.ts`

Creates the Hono application for `/api/*` only.

Major exports:

```ts
export type AppEnv = { Bindings: Env };
export const app: Hono<AppEnv>;
```

Responsibilities:

- Register domain list routes.
- Return JSON 404 for unknown API routes.
- Add a final API error handler that emits sanitized JSON.

Must not register asset or Agent routes.

### `src/worker/domain.routes.ts`

Registers browser-facing domain routes.

Major export:

```ts
export function registerDomainRoutes(app: Hono<AppEnv>): void;
```

Handlers:

```ts
GET / api / requests;
GET / api / tickets;
GET / api / po - logs;
```

Handler behavior:

- Read `page`, defaulting to 1 only if omitted.
- Read optional `status` for Requests and Tickets.
- Use fixed page sizes 4 (requests), 4 (tickets), and 8 (PO logs).
- Call typed Domain API RPC: `env.DOMAIN_API.listRequests(...)`, `listTickets(...)`, or `listPoLogs(...)`, each returning `RpcResult<PageResult<...>>`.
- On `ok: true`, return `result.data` (`PageResult<FeatureRequestDto>`, `PageResult<TicketDto>`, or `PageResult<PoLogDto>`) with `items`, `page`, `pageSize`, and `totalPages` passed through unchanged.
- On `ok: false` or a thrown RPC exception, log structured context (including `result.error.code` when present) and return the sanitized `502` `UPSTREAM_ERROR` response.

Authoritative method signatures come from the generated binding type. The file must not invent new backend operations.

### `src/worker/agent-proxy.ts`

Major exports:

```ts
export function isWingmanAgentPath(pathname: string): boolean;
export function isDevAgentPath(pathname: string): boolean;
export function proxyAgentRequest(request: Request, binding: Fetcher): Promise<Response>;
```

`proxyAgentRequest` forwards the original request through the ordinary Service Binding's `binding.fetch(request)` and returns the response directly.

Forbidden behavior:

- Reading WebSocket frames.
- Constructing a replacement socket pair.
- Reading or buffering streamed response bodies.
- Parsing chat messages.
- Rewriting tool parts.

### `src/worker/error-response.ts`

Major exports:

```ts
export interface ApiErrorResponse {
  error: {
    code: string;
    message: string;
  };
}

export function apiErrorResponse(status: 500 | 502, code: string, message: string): Response;
```

`code` is an open string. The UI Worker normally emits `UPSTREAM_ERROR` (502) or `INTERNAL_ERROR` (500).

Produces JSON with an explicit JSON content type. It never serializes raw exceptions.

### `src/worker/structured-log.ts`

Major exports:

```ts
export interface WorkerErrorLog {
  event: string;
  route: string;
  operation?: string;
  page?: number;
  status?: string;
  rpcErrorCode?: string;
  errorName: string;
  message: string;
  timestamp: string;
}

export function logWorkerError(entry: WorkerErrorLog): void;
export function errorMetadata(error: unknown): {
  errorName: string;
  message: string;
};
```

Uses `console.error(entry)`. Do not log secrets or complete user content.

### `src/hooks/use-persisted-conversation-id.ts`

Major interface:

```ts
export function usePersistedConversationId(storageKey: string): {
  conversationId: string;
  startNewConversation(): void;

```

Responsibilities:

- Lazy-read `localStorage`.
- Generate and persist `crypto.randomUUID()` if missing.
- Replace stored ID only after caller confirms.

The hook itself may accept a confirmation function, or pages may own confirmation and call a lower-level `replaceConversationId()` method. Both Wingman and Dev Agent IDs are stored only in `localStorage`, so a refresh reconnects to the same conversation.

## 18. Forbidden coding-agent substitutions

The coding agent must not:

- Create public routes for private backend Workers.
- Replace Domain RPC with a public Domain API.
- Add a separate Pages project.
- Add React Router or global state management.
- Store chat messages in `localStorage`.
- Store either Agent ID anywhere other than `localStorage`.
- Create a new Wingman or Dev Agent ID merely because the user switches tabs or refreshes.
- Skip confirmation when starting either fresh conversation.
- Implement Agent transport manually.
- Create a custom public Dev state endpoint.
- Call Wingman's programmatic `invokeTurn()` RPC from the browser.
- Hand-write a Domain API service interface instead of using the generated binding type.
- Show linked ticket IDs as links.
- Automatically load the final PO Logs page.
- Add polling or automatic refresh.
- Add automated test frameworks.
- Invent missing backend fields or operations.
